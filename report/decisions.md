# Decisions
1. **No wadi term (22 Nov 2026 answer from project lead).** DAS-map `intrinsic_risk_grid.m` has slope + road distance only; used unchanged. No wadi term was invented.
2. **Lambda per zone = TBD / PLACEHOLDER.** Makkah values are not reused; columns kept in `cells.csv` as the string `TBD`.
3. **Hot is forced** within R_hot_sub = 500 m [ASSUMED] of the 380 kV substation (OSM way 1317477365); k-means (k = 2) splits the remaining cells into Cold/Neutral. Sensitivity R_hot_sub 250/500/1000 m x cell 100/250/500 m in `results_zones/sensitivity.csv`.
4. **Risk roads** = DAS-map classes (motorway..tertiary + links); all roads are kept for drawing.
5. **Optimization source** = f51b223 from `full das/third_party/optimization`.
6. **No drones, UAVs or patrols** anywhere; cameras are the only verification asset.
7. **Framing factor 0.88 (twin camera).** The DAS-map formula dist = 53 x (Sudair bbox diagonal 10.73 km / Makkah 46.66 km) = 12.19 left the plant small, so only `dist` was scaled by 0.88 (az 180, el 30, fov 30, perspective and the fibre-bbox target are unchanged). The restyle then needed room for the new elements: final dist = 12.19 x 0.88 x 1.10 = 11.802.
8. **Single shelter (N = 1).** With one building the channels must start at the fence entry point and run one each way round the ring: 16.282 km each (lead-in 130 m counted) against R_DAS 20 km. Any N > 1 would need another shelter, so `place_fibre_sudair` errors instead of silently placing sites.
9. **Vertical exaggeration.** The site is flat (687-771 m): x2 shows nothing. x6 was tried first and tilted the plant too much, x4 is kept. Written in the attribution line.
10. **Hillshade.** From the real Copernicus DEM (smoothed 1 px), sun azimuth 315 deg (north-west), elevation 25 deg, multiplied into the Esri texture with weight 0.9 (1 on flat ground). Haze toward the far (north) edge only, max 0.40, none on the plant. DAS-map's `draw_terrain` uses no scene lights (FaceLighting none), so the shading is baked into the texture rather than adding camlight. Contours every 10 m from the same DEM; OSM has 174 waterway features in the AOI, 82 touch the drawn area and are drawn as thin blue-grey lines (none invented).
11. **Control room location.** OSM has no separate control-room building, so the centroid of the 380 kV substation polygon (way 1317477365) stands in for it; the 130 m lead-in depends on this.
12. **Display-only choices of the restyle** (all tagged in `parameters_sasg26.tsv`): energy along the channels comes from the Stage F engine profile; the calibration sine, the digging event and the other channel's event are masked to the median (they are not located on the fence); one isolated simulated noise spike above the detection threshold (ch 2) is not drawn as an alarm; the red glow is widened by 300 m. Adapted copies of DAS-map code (third_party untouched): `draw_fibre_sudair` (10 km corridor block removed), `draw_events_sudair` and `draw_assets_sudair` (UAV / patrol parts removed, sizes scaled to plant km), `draw_status_sudair` (Sudair rows).

## Fix round (twin3d registration and clean-up)
13. **Geo-registration bug found and fixed (imagery request, not the fibre data).** The 2x2 hi-res plant tiles were requested with a metric aspect (px:py from metres). The Esri export wants square pixels in degrees and, when the aspect differs, expands the extent: the tiles were stretched and the northern and southern tiles overlapped with a visible seam (features repeated 320 m apart). The request now uses the degree aspect (`make_shaded_textures`). The same mistake was in the intruder-map imagery fetch (`render_intruder_map`) and is fixed there too (`tex_intruder.jpg` refetched, figure re-rendered; no number changed).
14. **Draping.** The fibre, zone bands, substation, ground markers, pulses and contours now take their height from the same meshes that draw the terrain (detail mesh including its +0.004 lift, base mesh elsewhere) plus 0.006 km display lift (1.5 m real at x4; limit was 3 m x VERT_EXAG). The earlier ridge-dilated fibre height and the +0.05 km floating risk surface are gone (`draw_risk_sudair`).
15. **Registration proof.** `src/viz/check_registration.m` renders a top-down orthographic view (el = 90, VE 1) with the OSM boundary as a 1 px line over the same surface: `poster_figs/check_registration_{NW_strip,substation_notch,east_edge}.png` (0.8 x 0.53 km, 1200 x 800 px, 0.67 m/px). The line sits on the perimeter road / fence track in all three; maximum visible offset about 8 px = about 5 m (visual estimate; the imagery itself is 2.0 x 2.2 m/px, so smaller offsets cannot be resolved).
16. **No stair-step overlay.** The hi-res plant texture is blended into the base texture with a smooth alpha mask (75 m smoothstep) instead of a hard edge; risk cells are removed inside the fence and, outside, smoothed with alpha <= 0.25.
17. **Light pulses** are short bright segments on the fibre (0.2 km, white core x2.4 + cyan glow x3.4 of the line width, every 3 km), nothing wider than the fibre glow. **Zone bands** are +-50 m, alpha 0.35. **Intruder** marker and heat patch are draped, 2 rings, outer radius 0.30 km; the 300 m red display glow on the fibre is kept (ASSUMED: display only).
18. **Two versions.** `twin3d.png` / `twin3d_zoom.png` are clean (map only, small N arrow, small attribution in a semi-transparent white box). `twin3d_panels.png` has STATUS / legend / phi-OTDR panels in a strip below the map (`draw_trace_sudair`: walking / vehicle labels aligned left / right, shorter y label). Sizes: 2610x1500 (1.74:1) and 2000x1500 (4:3), 300 dpi.

## AI stage
19. **Same interface as full-das, no new classifier.** `third_party/fulldas_ai` is a read-only copy of full-das `ai_interface.m`, `ai_config.json`, `class_map.yaml` and the Brno confusion counts, in the full-das folder layout so the code runs unchanged. `use_real_ai = false` (stub).
20. **Runs.** Base mode `uniform` at both ends of Pc_DAS (0.983 from the copied file; 0.993 from a temporary copy with only Pc changed) and the Brno `confusion_counts` sensitivity through the interface's own `AI_CLASSIFIER_MODE` switch. One fixed seed (Threefry 1) per run.
21. **Calibration sine** is classified with true class `no_event` [ASSUMED] and excluded from the alarm logic. **Routing** follows full-das `respond_day`: threat class -> ALARM -> camera verification; a `vehicle` output for the access-road vehicle -> logged; other classes -> no alarm.
22. **Figure labels** (twin, STATUS panel, trace panel, intruder map) are built by `src/ai/ai_labels.m` from the base run (Pc 0.983); `tests/test_stageAI.m` checks they match `report/ai_results.md`.
